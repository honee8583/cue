# cue frontend

영화/공연 실시간 예매 서비스의 웹 프론트엔드.
(저장소 루트 `cue/`가 git 모노레포이고, 이 폴더는 그중 frontend 프로젝트)

## 스택
- 미정

## 실행 방법
- 스택 결정 후 작성
- backend가 먼저 실행되어 있어야 함 (`backend/CLAUDE.md` 참고)

## 작업 절차 (반드시 따를 것)
1. 요청받은 기능을 구현한다.
2. 테스트를 실행한다 (테스트 명령은 스택 결정 후 작성).
3. 실패하면 원인을 찾아 코드를 고치고 다시 실행한다. 모두 통과할 때까지 반복한다.
   - 테스트를 통과시키려고 테스트 자체를 지우거나 약하게 고치지 않는다.
4. **커밋하지 않는다.** 커밋/푸시는 사용자가 명시적으로 요청할 때만 한다.

## 커밋 규칙 (커밋을 요청받았을 때)

### 형식
```
<타입>(<범위>): <제목>
- <내용>
- <내용>
```
예시:
```
feat(movie): 영화 목록 페이지 추가
- /movies 페이지에서 영화 목록 조회
- 페이지 이동(페이지네이션) 버튼 추가
```

- **타입**
  - `feat`: 새 기능
  - `fix`: 버그 수정
  - `refactor`: 동작 변화 없는 코드 구조 개선
  - `test`: 테스트 추가/수정
  - `docs`: 문서 (CLAUDE.md, README 등)
  - `chore`: 설정, 의존성, 빌드 등 기타
- **범위**: 변경된 도메인이나 영역 (예: `movie`, `booking`, `api`, `config`, `claude`)
- **제목**: 한국어로, 무엇을 했는지 간결하게. 끝에 마침표를 쓰지 않는다.
- **내용**: `- `로 시작하는 줄로 변경 사항을 나열한다.

### 단위
- 하나의 커밋에는 하나의 목적만 담는다. 성격이 다른 변경은 나눠서 커밋한다.
  - 예: 기능 구현 / 관련 없는 리팩터링 / 설정 변경 → 각각 별도 커밋
- 기능과 그 기능의 테스트는 같은 커밋에 넣는다.
- 각 커밋 시점에도 테스트가 통과하는 상태여야 한다.
- 커밋 전에 어떻게 나눌지 먼저 보여준다.

## 연동
- backend API: http://localhost:8000 (문서: /docs)

## 규칙
- 사용자는 입문자. 구현한 기능은 처음 배우는 사람 기준으로 한국어로 설명한다.
